# ADR-0002: Проп `autofocus` у полей формы

**Status:** Proposed (применено в tech.md v6, ждёт подтверждения владельца)
**Date:** 2026-09-26
**Deciders:** владелец

## Context

S2-02 AC7: после ответа 400 фокус встаёт на первое ошибочное поле, с JS и без. С JS фокус ставит скрипт. Без JS браузер фокусирует поле только по атрибуту `autofocus` в HTML, который отдаёт `/lead`. В контракте примитивов (раздел 11) у Select, Checkbox и PhoneInput такого пропса нет.

## Decision

Добавить `autofocus?: boolean` в пропсы Input, Textarea, Select, Checkbox, PhoneInput. LeadForm передаёт `true` только первому полю с ошибкой после отправки без JS.

## Options Considered

### Option A: проп `autofocus` (выбрано)
| Dimension | Assessment |
|-----------|------------|
| Complexity | Low: одно необязательное поле, уходит в нативный элемент |
| Cost | Нет миграций, API и типы не меняются |
| Scalability | Не влияет |
| Team familiarity | Стандартный атрибут HTML |

**Pros:** AC7 выполняется без JS; расширение, а не изменение контракта.
**Cons:** `autofocus` на странице ответа сдвигает прокрутку к полю (здесь это и нужно).

### Option B: якорь `/lead#<поле>` через редирект
**Pros:** примитивы не меняются.
**Cons:** редирект теряет значения формы и ошибки (или нужен session-state); якорь прокручивает, но не фокусирует.

## Trade-off Analysis

Только вариант A выполняет AC7 без JS и без состояния на сервере.

## Consequences

- Проще: любая форма может так же вести фокус без JS.
- Сложнее: ничего.
- Пересмотреть: не требуется.
