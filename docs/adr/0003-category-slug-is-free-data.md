# ADR-0003: Slug категории перестаёт быть enum

**Status:** Proposed (применено в tech.md v14, ждёт подтверждения владельца)
**Date:** 2026-11-19
**Deciders:** владелец

## Context

Пять категорий жили подмножеством `ProductKind`: `CATEGORY_SLUG_CHOICES` задавал `choices` у `Category.slug`, `CategoryAdmin` наследовал `ReferenceRowAdmin` (без добавления и удаления), `sync_reference_data` создавал ровно пять строк, а `CategorySlugEnum` закреплял тот же набор в `openapi.yaml` и в TS-типах. Из этого следовало два пробела: контент-менеджер не мог завести свою категорию, а вид `other` («Другое») не имел ни карточки, ни страницы `/catalog/other`, хотя в форме заявки он выбирался.

Enum давал два полезных свойства, которые теперь надо чем-то заменить: svelte-check ловил несуществующий slug на фронте, а `PRODUCT_KIND_LABELS[item.category]` переводил slug в название без запроса к API.

## Decision

`Category.slug` становится свободным `SlugField(max_length=32, unique=True)`. Админка получает добавление и удаление, slug подставляется из названия при создании и дальше только читается. `sync_reference_data` сеет шесть строк из `CATEGORY_SEED` только на пустой таблице. `CategorySlugEnum` уходит из схемы, `CategorySlug` в TS это `string`, а DTO `GalleryItem` расширяется полем `category_title`: название приезжает с данными, а не выводится из slug. `Lead.product` остаётся закрытым `ProductKind` до S2-17.

## Options Considered

### Option A: свободный slug, названия из API (выбрано)
| Dimension | Assessment |
|-----------|------------|
| Complexity | Medium: одна `AlterField`, админка, подпись миниатюры из DTO |
| Cost | Миграция расширяющая, данные не переносятся |
| Scalability | Категорий сколько нужно, деплой на это не требуется |
| Team familiarity | Обычная CRUD-модель Django |

**Pros:** закрывает оба пробела одной правкой; удалённая категория не возвращается деплоем; название всегда совпадает с тем, что в админке.
**Cons:** enum больше не ловит опечатку в slug на этапе типов; защиту берут на себя `unique=True`, `SlugField` и 404 на неизвестный slug.

### Option B: оставить enum, дописать в него `other`
**Pros:** одна строка, enum и типизация целы.
**Cons:** даёт только «Другое»; свои категории по-прежнему требуют правки кода, миграции и деплоя. Просьба владельца закрывается наполовину.

### Option C: enum плюс таблица своих категорий
**Pros:** известные пять остаются типизированными.
**Cons:** два источника истины для одного списка: два селектора, два пути в DTO, два правила сортировки. Сложность растёт там, где выгоды нет.

## Trade-off Analysis

Вариант B не решает поставленную задачу, вариант C платит постоянной сложностью за типизацию пяти строк. Вариант A теряет проверку slug на типах, но эта проверка и так не доходила до данных: slug в URL приходит от посетителя строкой, и 404 на неизвестную категорию уже был в контракте (раздел 7). Поэтому цена A ограничена редакторскими опечатками в админке, где ошибку видно сразу на странице категории.

## Consequences

- Проще: категории заводятся без разработчика; `other` становится обычной строкой данных, как и любая новая категория.
- Сложнее: подпись миниатюры зависит от поля DTO, а не от константы фронта, поэтому новый контракт `GalleryItem.category_title` надо держать заполненным в обоих селекторах.
- Пересмотреть: S2-17 снимает `choices` с `Lead.product` и строит список формы из категорий. До него CTA своей категории открывает форму без предвыбора вида.
