# Фабрика Уюта

Сайт-визитка мебельного производства: главная с секциями, страницы направлений, форма заявки и админка для контента. Заявка сначала попадает в Postgres, затем воркер доставляет её в Google-таблицу с ретраями, поэтому недоступность Google заявку не теряет.

Сайт работает без JavaScript: форма отправляется обычным POST, диалоги и маска телефона только улучшают опыт. Тема одна, светлая, адаптив от 360 px, тексты на русском.

## Стек

| Слой | Технологии |
|---|---|
| Фронтенд | SvelteKit 2, Svelte 5 (только руны), TypeScript strict, Tailwind 4, shadcn-svelte, adapter-node |
| Бэкенд | Python 3.13, Django 5.2 LTS, DRF, drf-spectacular, gunicorn |
| База | PostgreSQL 18 |
| Очередь | outbox в таблице заявок, процесс `run_sheets_worker`, без брокера |
| Интеграция | Google Sheets API v4, сервисный аккаунт |
| Edge | Caddy 2: TLS, маршрутизация, раздача media |
| Окружение | Docker Compose, uv, pnpm |

Браузер ходит только на SvelteKit. SvelteKit работает как BFF и зовёт Django по внутренней сети с заголовком `X-Internal-Token`; снаружи `/api/*` отдаёт 404.

```
Браузер → Caddy ─┬─ /api/*                      → 404
                 ├─ /media/*                    → том media
                 ├─ /<админка>, /django-static/ → backend:8000
                 └─ остальное                   → frontend:3000

frontend (SvelteKit) → backend (Django) → Postgres ← worker → Google Sheets
```

## Локальная разработка

Нужны Docker, Node 24 с pnpm и [uv](https://docs.astral.sh/uv/).

```bash
cp .env.example .env
```

```bash
make dev
```

```bash
pnpm -C frontend dev
```

`make dev` поднимает Postgres, Django и воркер в Docker, `pnpm dev` запускает фронт на `http://localhost:5173`. Vite проксирует `/media`, `/django-static` и путь админки на Django, так что админка открывается там же.

Первый запуск наполняет базу демо-данными и создаёт пользователя админки:

```bash
make migrate && make seed
```

```bash
cd backend && uv run python manage.py createsuperuser
```

`make seed` создаёт справочники (5 направлений, 4 слота фото, настройки сайта, группы прав) и демо-контент: фото, 12 работ галереи, контакты и три заявки. Команда идемпотентна, `seed_demo --reset` пересоздаёт демо-данные.

## Тесты

Тесты выводятся из критериев приёмки задачи, номер AC стоит в имени теста. Слои:

- бэкенд: pytest с pytest-django, Hypothesis на чистых функциях, Schemathesis по всем операциям API, `responses` на Google-клиенте, pytest-socket запрещает сеть;
- фронтенд: vitest (компонентные тесты в браузерном режиме на Chromium), fast-check на доменной логике;
- E2E: Playwright на 1440 и 360 px, axe на затронутых страницах, у формы отдельный прогон с выключенным JavaScript.

Обязательные проверки на стыках: ответы API против схемы, маска телефона против нормализации (`contracts/fixtures/phone-cases.json` читают обе стороны), идемпотентность воркера, пути ошибок внешнего клиента.

```bash
make gate && make e2e
```

## Деплой на VPS

Production поднимается одним файлом `compose.prod.yml`: Caddy, Postgres, Django, воркер и SvelteKit. Образы собираются на сервере из этого же репозитория, реестр образов и вторая машина не нужны.

### Что потребуется

- VPS с Linux и Docker с плагином **Compose v2**. Проверить: `docker compose version` через пробел должна отвечать. Старый `docker-compose` через дефис из репозиториев дистрибутива не подойдёт: он не понимает ни ключ `name`, ни профили. Если команды нет, поставьте Docker с плагинами официальным скриптом: `curl -fsSL https://get.docker.com | sh`.
- Сборке фронта нужно около 2 ГБ оперативной памяти: на сервере меньшего размера включите swap до первого деплоя.
- Домен с A-записью на IP сервера, открытые порты 80 и 443. Caddy сам получит сертификат Let's Encrypt и продлит его.
- Ключ сервисного аккаунта Google, если заявки должны уходить в таблицу.

### Первый запуск

```bash
git clone https://github.com/snowfallite/fabrika-uyuta.git /opt/fabrika/app
```

```bash
cd /opt/fabrika/app && cp .env.example .env
```

Заполните `.env`. Руками задаются только эти строки, по порядку файла:

| Переменная | Значение |
|---|---|
| `DOMAIN` | домен сайта без схемы и слэша, например `fabrika-uyuta.ru` |
| `ACME_EMAIL` | ваша почта: на неё Let's Encrypt пишет об истечении сертификата |
| `POSTGRES_PASSWORD` | длинный случайный пароль |
| `DJANGO_SECRET_KEY` | случайная строка от 50 символов |
| `DJANGO_DEBUG` | `false` |
| `DJANGO_ADMIN_PATH` | секретный путь со слэшем на конце, не `admin/` |
| `INTERNAL_API_TOKEN` | случайная строка от 32 символов |
| `CONSENT_VERSION` | дата версии текста согласия, например `2026-12-01` |
| `ENABLE_TEST_ENDPOINTS` | `false` |
| `SHEETS_BACKEND` | `google` для боевой таблицы, `fake` чтобы запустить сайт без Google |
| `GOOGLE_SERVICE_ACCOUNT_FILE` | `/run/secrets/google-sa.json` при `SHEETS_BACKEND=google` |
| `GOOGLE_SPREADSHEET_ID` | ID таблицы заказчика из её URL |
| `ALERT_EMAIL`, `EMAIL_*` | письма о застрявших заявках; пустой `ALERT_EMAIL` выключает алерты, пустой `EMAIL_HOST` пишет их в лог воркера |

Почта для алертов работает только по неявному SSL: `EMAIL_PORT=465` и `EMAIL_USE_SSL=true`. Переменной для STARTTLS в контракте нет, поэтому порт 587 не подойдёт. В `EMAIL_HOST_PASSWORD` нужен пароль приложения: обычный пароль от ящика провайдеры для SMTP не принимают. `DEFAULT_FROM_EMAIL` должен совпадать с ящиком из `EMAIL_HOST_USER`, иначе провайдер отклонит отправку.

Секреты удобно сгенерировать на сервере:

```bash
openssl rand -base64 48 && openssl rand -hex 24
```

Остальное `compose.prod.yml` подставляет сам, и значения этих строк в `.env` на production не влияют: `APP_ENV`, `PUBLIC_APP_ENV`, `POSTGRES_HOST`, `MEDIA_ROOT`, `API_INTERNAL_URL`, `ADDRESS_HEADER`, `XFF_DEPTH`, а из `DOMAIN` выводятся `DJANGO_ALLOWED_HOSTS`, `DJANGO_CSRF_TRUSTED_ORIGINS`, `PUBLIC_SITE_URL` и `ORIGIN`. Блок `# e2e` в production не нужен.

Ключ сервисного аккаунта положите рядом: `/opt/fabrika/app/google-sa.json`. Файл и `.env` в `.gitignore`, `git pull` их не трогает.

Google-таблицу готовят один раз: лист `Заявки`, в строке 1 заголовки колонок A..H из раздела 8.1 `tech.md`, сервисному аккаунту выдан доступ «Редактор». Команда `sheets_check` в release-шаге сверит заголовки и не даст выкатиться на неправильную таблицу.

Затем:

```bash
deploy/deploy.sh
```

```bash
docker compose -f compose.prod.yml exec backend python manage.py createsuperuser
```

### Обновление и откат

```bash
cd /opt/fabrika/app && git pull && deploy/deploy.sh
```

`deploy.sh` делает пять шагов: проверяет, что юридические тексты не черновики, собирает образы, прогоняет release-шаг (`check --deploy`, миграции, таблица кэша, справочники, проверка заголовков таблицы), поднимает стек с ожиданием healthy и прогоняет smoke-тест. Упавший release-шаг прерывает деплой до того, как тронуты работающие контейнеры: сайт продолжает отвечать старой версией.

Откат: вернуться на предыдущий коммит или тег и выкатиться снова. Это безопасно, потому что миграции только расширяющие.

```bash
git checkout v1.0.0 && deploy/deploy.sh
```

### Эксплуатация

| Задача | Команда |
|---|---|
| Логи | `docker compose -f compose.prod.yml logs -f backend worker` |
| Состояние | `docker compose -f compose.prod.yml ps` |
| Здоровье | `curl https://<домен>/healthz` |
| Ручной smoke | `deploy/smoke.sh https://<домен>` |
| Бэкап | `deploy/backup.sh` |

`/healthz` отвечает 503, если недоступна база или воркер перестал писать heartbeat. Подключите внешний мониторинг с опросом раз в минуту.

Ночной бэкап базы и media ставится в cron, 14 дней хранятся на сервере и копия уходит в S3-совместимое хранилище, если задан `/opt/fabrika/backup.env`:

```
30 3 * * * /opt/fabrika/app/deploy/backup.sh >> /var/log/fabrika-backup.log 2>&1
```

Восстановление по шагам: [deploy/RESTORE.md](deploy/RESTORE.md).

## Админка

Путь админки задаётся `DJANGO_ADMIN_PATH` и в production не равен `admin/`. django-axes блокирует пару логин и IP на час после 5 неудачных входов.

Две группы прав создаются автоматически:

- «Контент»: фото слотов, обложки направлений, галерея работ, контакты;
- «Заявки»: просмотр заявок и действие «Повторить отправку» в таблицу.

Фото проходят через пайплайн: мастер JPEG до 2560 px без EXIF, варианты WebP на 640, 1280 и 1920 px, цвет-заглушка на время загрузки. Принимаются JPEG, PNG и WebP до 20 МБ, длинная сторона от 800 px. В галерею направления можно загрузить до 20 файлов за раз, пакет атомарный.

## Заявки и Google-таблица

Форма пишет заявку в Postgres со статусом «Ожидает отправки». Воркер раз в несколько секунд берёт до 10 заявок, проверяет по ID, нет ли строки в таблице, и дописывает недостающие. Повтор после ошибки идёт с экспоненциальной задержкой и джиттером, около 5 часов на 12 попыток, затем статус «Ошибка отправки». Дублей не бывает даже если ответ Google потерялся: перед записью воркер ищет ID в колонке A.

Колонки A..H принадлежат приложению, свои колонки менеджеры добавляют правее H. Текст вида `=IMPORTXML(...)` из формы попадает в ячейку как текст: запись идёт в режиме `RAW`.

Если заявки застревают, на `ALERT_EMAIL` уходит письмо со списком публичных ID и ссылкой на админку, не чаще раза в 30 минут. Персональных данных в письме нет.

## Персональные данные

- Первичная запись заявки идёт в Postgres на сервере, Google-таблица получает уже собранные данные.
- Согласие на обработку оформлено отдельным документом на `/consent`, чекбокс по умолчанию выключен, в заявке хранятся версия согласия и время.
- На сайте нет иностранных счётчиков, шрифтовых CDN, капч и встраиваемых карт. Шрифты раздаются со своего домена, карта открывается ссылкой.
- ФИО, телефон и комментарий не попадают в логи, ошибки, алерты и фикстуры.

Передача в Google это трансграничная передача: заказчик подаёт уведомление в Роскомнадзор до запуска, политика и согласие её упоминают.

**Тексты `/privacy` и `/consent` сейчас черновики.** В компонентах стоит маркер `LEGAL_TEXT_PENDING`, на страницах видна плашка «Проект документа. Текст проверяет юрист.» `deploy.sh` с этим маркером останавливается и не выкатывает production. Замените тексты на проверенные юристом, заполните реквизиты оператора и срок хранения в квадратных скобках, уберите маркер и плашку.

## Порядок работы

`tech.md` это источник истины: стек, схема базы, API, контракты UI, тексты формы, задачи. Приоритет такой: `tech.md` → `CLAUDE.md` → существующий код. Код разошёлся с `tech.md`: прав `tech.md`.

Контракты заморожены. Нужен новый тип, поле, эндпоинт, пропс, переменная окружения или зависимость, которых нет в `tech.md`: сначала правка `tech.md` с бампом версии и строкой в Changelog, потом генераторы, потом код. Всё в одной ветке и одном PR. За этим следят три рубежа: процедура `CONTRACT GAP` в `CLAUDE.md`, джоба `contract-guard` в CI и правила доступа в `.claude/settings.json`.

Одна задача это одна ветка и один PR. Заголовок PR по схеме `type(scope): summary (ABC-n)`, коммиты по Conventional Commits, код и комментарии на английском, тексты интерфейса на русском.

CI на каждый PR гоняет пять джоб: `front` (формат, линт, типы, knip, юнит-тесты, сборка), `back` (ruff, mypy, миграции, pytest), `drift` (сгенерированные схема и типы совпадают с кодом), `e2e` (полный стек и Playwright) и `contract-guard`. Деплой в CI не входит: его запускает владелец на сервере.
