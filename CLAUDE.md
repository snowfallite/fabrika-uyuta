# CLAUDE.md

Сайт-визитка «Фабрика Уюта». Работает один человек: владелец совмещает тимлида и разработчика, файлов ролей нет. Этот файл задаёт порядок работы сессии. Ядро проекта импортируется ниже и загружается в каждую сессию автоматически.

<!-- Проверка загрузки: /context в сессии показывает CLAUDE.md и tech.md в Memory files. Файл лежит в корне репозитория рядом с tech.md. -->

@tech.md

## Источник истины

- `tech.md`: стек, схема БД, API, контракты, UI-примитивы, тесты, конвенции, задачи. Подчиняйся ему дословно.
- Приоритет: `tech.md` > этот файл > существующий код. Код расходится с `tech.md`: сообщи владельцу, `tech.md` под код не подгоняй.
- В начале сессии назови версию ядра (`Версия: vN`) и статус каркаса (`Каркас: ...`) из шапки `tech.md`.

## Цикл задачи

1. Одна задача за сессию: ID из разделов 21 и 22 (`S1-xx`, `S2-xx`) и ID Linear (`ABC-n`). Задача не названа: спроси.
2. Гейты. `S1-xx` строго по порядку: предыдущая задача в `main`. `S2-xx` при `Каркас: не готов` не начинай. Проверь «Зависит от». Гейт не пройден: стоп, сообщи.
3. Ветка от свежего `main`: имя из Linear или `<type>/ABC-<n>-<slug>`.
4. План до кода: файлы по раскладке эталона Hero (раздел 5), контракты с номерами разделов, тест на каждый AC. Покажи план. План выходит за раскладку задачи: жди ответа владельца.
5. Тесты из AC до кода, номер AC в имени теста (раздел 17). Skill `engineering:testing-strategy` установлен: используй его для плана тестов.
6. Код только в файлах плана. Слайс Стадии 2 заменяет заглушку каркаса поведением, схему API и модели не меняет.
7. Коммиты по ходу работы (18.2): маленькие, логические, `make check-fast` перед каждым. В `main` не пушь.
8. Перед PR: `make gate`, для UI-задачи ещё `make e2e`. Пройди DoD (19.1) и чек-лист ревью (19.2) по пунктам.
9. PR через `gh pr create`, заголовок и тело по 18.3. Мёрдж, теги и релизы делает владелец.
10. Отчёт владельцу: что сделано, AC → тест, что не сделано, открытые `CONTRACT GAP`.

## CONTRACT GAP

Контракты перечислены в разделе 3 `tech.md`. Стоп, если:
- нужен тип, поле, эндпоинт, код ответа, пропс или вариант примитива, переменная окружения, текст UI или зависимость, которых нет в `tech.md`;
- нужна правка замороженного пути (раздел 3);
- `tech.md` расходится с фактами: версия пакета, API библиотеки, поведение сервиса.

Код с выдуманным контрактом не пиши. Выдай блок:

```text
CONTRACT GAP
Задача: <S?-??> (<ABC-n>), tech.md v<N>
Нужно: <что именно>
Где: <раздел tech.md, файл>
Зачем: <какой AC без этого не закрыть>
Форма: <точный код: поле модели, DTO, пропс, строка .env, версия пакета>
Затронет: <миграции, openapi.yaml, api.d.ts, фикстуры, другие задачи>
Пока жду: <что делаю на локальной заглушке> | ничего
```

- Жди решения владельца. Продолжай только часть задачи, не зависящую от пробела. Заглушка живёт в файлах задачи и не выдаёт себя за контракт.
- Принято: процедура раздела 3. Коммит `docs(tech): vN <summary>` раньше кода, затем `make migrations` и `make gen`, затем код. Одна ветка, один PR.
- Отложено: владелец заводит задачу Linear с меткой `contract-change`, текст блока в описание.
- Контракт меняется только расширением. Удаление и переименование: отдельная задача, миграции в два релиза (15.1).

## Запрещено

- Выдумывать контракты.
- Править руками миграции, `contracts/openapi.yaml`, `frontend/src/lib/types/api.d.ts`. Генерация: `make migrations`, `make gen`. Data-миграции не писать.
- Менять `template/`. Шаблон только читать и переносить вёрстку в компоненты.
- Трогать файлы вне плана задачи. Нужна правка вне плана: сообщи.
- Писать самописный UI при наличии примитива (раздел 11). Цвета только токенами.
- Писать ПДн (ФИО, телефон, комментарий) в логи, ошибки, алерты, фикстуры. В тестах только фиктивные данные.
- Ходить в сеть в юнит- и интеграционных тестах. Google только через фейк или `responses`.
- Синтаксис Svelte 4: `export let`, `$:`, `on:event`, `<slot>`, `$app/stores`.
- Добавлять зависимости без `CONTRACT GAP`.
- Глушить проверки (`eslint-disable`, `@ts-ignore`, `# type: ignore`, `.skip`, `xfail`) без причины в комментарии и в описании PR.
- Читать `.env` и ключ сервисного аккаунта; класть секреты в код и коммиты.
- Сочинять юридические тексты: до текста от заказчика ставь маркер `LEGAL_TEXT_PENDING` (13.2).
- Мёрджить PR, пушить в `main`, ставить теги.

## Команды

```text
make dev                 # db, backend, worker в Docker
pnpm -C frontend dev     # фронт на localhost:5173
make migrations          # после правки схемы (раздел 6)
make migrate             # migrate + createcachetable
make gen                 # openapi.yaml и api.d.ts
make seed                # справочники и демо-данные
make check-fast          # svelte-check + mypy, перед каждым коммитом
make test                # vitest + pytest
make gate                # всё, что проверяет CI, кроме E2E
make e2e                 # полный стек и Playwright
```

## Язык и проза

- Код, идентификаторы, комментарии, коммиты, PR: английский. Тексты UI и `verbose_name`: русский.
- Ответы владельцу: русский, кратко, по делу.
- Коммиты, PR, комментарии, правки `tech.md`: дисциплина `stop-slop`. Активный залог или императив, конкретика, без длинного тире, без филлеров.
